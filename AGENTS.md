# AGENTS

Гайд для ИИ-агентов по проекту **summarizer** — телеграм-бот, который принимает
ссылку (статья или YouTube-видео) и возвращает краткий пересказ на русском.

Полный план и принятые решения — в [PLAN.md](PLAN.md). Запуск — в [README.md](README.md).

## Старт за 30 секунд

```sh
# 1. Node только через nvm — добавь в PATH в КАЖДОМ bash-вызове (state не персистится):
export PATH="$HOME/.nvm/versions/node/v22.22.3/bin:$PATH"

# 2. Зависимости (если ещё не стоят) и проверка, что всё зелёное:
npm install
npm run check          # typecheck + тесты — запускай после каждого изменения

# 3. Запуск бота (нужен заполненный .env, см. README):
npm run dev
```

Что делать дальше — открытые пункты в [PLAN.md](PLAN.md) (Этап 4: webhook, SQLite-кэш).
Перед коммитом: `npm run check` зелёный + обнови PLAN/README/AGENTS, если менял поведение.

## Стек

- **TypeScript / Node.js 22.12+**, ESM (`"type": "module"`, `module: NodeNext`).
- **grammY** — телеграм-бот. **rdrr** — извлечение текста (как библиотека).
- **LLM** — любой OpenAI-совместимый API через `openai` SDK; провайдер задаётся
  `LLM_BASE_URL` + `LLM_API_KEY` (дефолт — OpenRouter).
- **zod** — валидация env, **pino** — логи. Оценка токенов — эвристика (символы÷3),
  без зависимости-токенайзера.

> ⚠️ Node ставится через **nvm** (`v22.22.3`); в системном PATH его может не быть.
> Перед командами: `nvm use 22` или `export PATH="$HOME/.nvm/versions/node/v22.22.3/bin:$PATH"`.

## Команды

```sh
npm run dev        # tsx watch — разработка
npm run typecheck  # tsc --noEmit (включая тесты)
npm test           # node:test через tsx — юнит-тесты (src/**/*.test.ts)
npm run format     # prettier --write . (конфиг — .prettierrc.json)
npm run check      # typecheck + test + format:check (запускай перед коммитом)
npm run build      # tsc -p tsconfig.build.json → dist/ (без *.test.ts и scripts/)
npm run search:smoke -- "запрос"   # живой поиск YouTube без бота, LLM и .env
npm start          # node dist/bot.js (прод)
```

**Тесты:** встроенный `node:test` + `node:assert`, без внешних зависимостей. Файлы
рядом с кодом (`*.test.ts`). Покрыты чистые модули (formatter, url, парсинг
config, разбор выдачи и список `/search`, разбор файлов, доступ, имена, отчёты `/stats`),
репозитории `db/` (на `:memory:`) и middleware доступа (фейковый ctx). Сетевые вызовы (rdrr, OpenRouter) в юнит-тестах не дёргаем — для них чистую
логику выносим в тестируемые функции (напр. `decideAccess`, `retryAfterMs`).

## Архитектура

Перед всеми пайплайнами — **доступ** (Этап 9): `access` → `rateLimit` → админские команды
(`bot.filter(isAdmin)`) → остальные хендлеры. Незнакомец → заявка владельцу с кнопками;
решение — чистая `decideAccess`. Пользователи и статистика — SQLite (`db/`).

Три пайплайна:

- **Пересказ** (любой текст): `onLink` → `extract` → `summarize` → `formatter` → HTML в чат.
  Общий путь — `summarizeSource(source)`: источник отдаёт текст + шапку. Присланный файл
  идёт туда же: `onDocument` → `checkDocument` → скачивание → `readDocument` → `summarize`.
- **Поиск** (`/search`): `onSearch` → `searchYoutube` → список со ссылками и командами
  `/sum_<id>` / `/art_<id>` → `onSearchCommand` → тот же `runSummary` / `runArticle`.
- **Статья** (`/article`): `onArticle` → `extract` → `buildArticle` → `.md`-файлом.
  Видео → `chunker` → LLM по кускам последовательно → склейка. Не видео → markdown от rdrr
  под нашей шапкой, **без LLM**.


## Соглашения и подводные камни

- **Секреты в логах.** `logger` чистит готовую строку от `BOT_TOKEN` и `LLM_API_KEY`
  (`lib/redact.ts`): grammY кладёт в сообщение ошибки полный URL с токеном. Пишешь в
  консоль мимо `logger` — секрет уедет в лог как есть.
- **`npm run check` гоняет хук** (`.claude/hooks/check.sh`, событие Stop в
  `.claude/settings.json`): после каждого ответа Claude, и при падении возвращает ему
  строки с ошибками. Руками из агента запускать не нужно.
- **Форматирование — prettier** (`.prettierrc.json`: одинарные кавычки, ширина 80;
  в YAML кавычки не трогаем). Markdown под `.prettierignore` — доки свёрстаны руками.
  `npm run check` падает на неотформатированном коде.
- **ESM-импорты с расширением `.js`** (требование NodeNext), даже для `.ts`-файлов.
- **rdrr**: текст лежит в поле `content` (не `markdown`); `title`/`wordCount`/`type` —
  на верхнем уровне `ParseResult`. Грузим динамически (`await import('rdrr')`).
- **rdrr и видео**: `type` бывает `youtube | webpage | github | stackoverflow | x-profile | x-status`.
  **Видео — только YouTube**, Vimeo и прочих нет. У youtube есть `chapters[]` и `transcript[]`
  (у сегмента — `chapterIndex`), а `content` — плоский дамп с таймкодами, для статьи не годится:
  строим из `transcript[]`. Для webpage `content` — **голое тело без H1**, шапку добавляем сами.
- **rdrr не знает ссылок `youtube.com/live/ID`**: id видео он ищет только в `?v=`, `youtu.be/`,
  `/embed/`, `/shorts/`, а `/live/` уходит в него обычной веб-страницей. Это то же видео (эфир
  или его запись), поэтому `extractUrl` (`lib/url.ts`) переписывает его в `watch?v=ID`.
- **Лимит выхода ≠ контекст.** Для `/article` объём ответа сравним со входом. В контекст всё
  влезает, но модель имеет прайор на длину ответа (~1–2k токенов) и на большом куске **тихо
  скатывается в пересказ**. Поэтому и нужен `chunker` — маленький кусок она разворачивает
  честно. Метрика, которой это ловится: `ratio = длина статьи / длина расшифровки` ≳ 0.5.
- **Тот же прайор ломал и пересказ**: без явного ориентира модель выдаёт ~одинаковые 3-5
  блоков и на заметке, и на часовом транскрипте. Лечится в `summaryBudget` (`summarizer.ts`):
  `chars = clamp(12·√длина, 300, 7000)`, `blocks ≈ chars/420` — ориентир уезжает **в
  user-промпт** (`renderBudget` в `prompts.ts`), а не в системный: он зависит от конкретного
  текста и так переживает подмену `SYSTEM_PROMPT_FILE`. Корень, а не линия: на длинном
  материале доля новых тем падает, линейный рост дал бы простыню. `blocks = 0` (короткий
  текст) — особый случай: просим связную суть без блоков вовсе. Кривая правится константами
  в `summarizer.ts`, контрольные точки прибиты тестами. Ловится по логам: `targetChars`
  против `actualChars` в строке `request`.
- **Новая команда добавляется в двух местах:** `commands.ts` (имя, описание, справка) и
  `bot.command()` в `bot.ts` (хендлер). Хендлеры в реестр не кладём: `/help` нужен список,
  а списку — хендлер `/help`, вышел бы цикл импортов (тот же приём, что с `SummaryBudget`).
  От рассинхрона страхует тест в `commands.test.ts`: он **читает исходник `bot.ts`** и
  сверяет имена из `bot.command('…')` с реестром. Импортировать `bot.ts` в тесте нельзя —
  на верхнем уровне он поднимает polling. Регистрации должны идти **до**
  `bot.on('message:text')`, иначе `/summary <url>` съест общий обработчик текста.
- **Результат приходит ответом на сообщение со ссылкой** (`lib/reply.ts`): обработка идёт
  десятки секунд, а у `/article` — минуты, за это время чат уезжает. `allow_sending_without_reply`
  там не для красоты: если сообщение, на которое отвечаем, успели удалить, Telegram иначе
  отобьёт отправку целиком. Многочастный пересказ идёт цепочкой: часть 1 отвечает на ссылку,
  каждая следующая — на предыдущую (id берётся у ответа `ctx.reply`).
- **Вызывать LLM только через `llm/complete.ts`.** Логика фолбэков и 429 тонкая — не дублируй.
- **Расход привязывается к пользователю через контекст запроса** (`lib/requestContext.ts`,
  AsyncLocalStorage). Хендлер оборачивает работу в `withRequest(…, command, fn)` — строка в
  `requests`; `complete()` сам пишет каждый ответ провайдера в `llm_calls` через
  `currentRequest()`. **Новый путь к LLM — только внутри `withRequest`**, иначе расход не
  попадёт в статистику (молча). Сбой записи статистики — `warn`, ответ пользователю не ломается.
- **SQL — только строковым литералом** в `prepare()`/`exec()`, значения — параметрами `?`.
  `db/sqlGuard.test.ts` читает исходники `src/db/*.ts` и падает на `${…}`, `+` и переменной
  в аргументе. Побочный эффект: в `src/db` нельзя `RegExp.exec` — используй `String.match`.
  Фильтр «по одному пользователю или по всем» — условием `(? IS NULL OR user_id = ?)`.
- **Содержимое чужих запросов не храним и не логируем** (решение владельца). В базе нет url,
  заголовков, поисковых запросов, имён файлов. В логах поля `url`/`title`/`query`/`file` —
  только через `sourceLogFields(isAdmin, …)`: для не-владельца `host` и `ext`. Поле `err`
  сериализует `lib/errorLog.ts`: вырезает `payload` (у `GrammyError` там текст сообщения,
  подпись, файл) и `metadata` (у OpenRouter — фрагмент входа). Не обходи его своим `err`.
- **Админские команды** регистрируются на `admin = bot.filter(isAdmin)` (`admin.command`), в
  реестре `commands.ts` — с `admin: true`: в `/help` их нет, меню владельцу ставится
  отдельно (`setMyCommands` со `scope: chat`). Кнопки заявки работают только по `pending`
  (`onlyIfPending`) — старая кнопка не перебьёт решение командой.
- **`node:sqlite` грузится динамически** (`openDatabase`): статический импорт печатает
  ExperimentalWarning раньше любого нашего кода, а так мы глушим ровно его. В тестах и коде
  импортируй из `node:sqlite` только типы (`import type`).
- **Доступ fail closed:** ошибка базы в `access` → «Временная ошибка», дальше не пускаем.
  Владелец (`ADMIN_USER_ID`) проходит всегда, даже без строки в базе; его профиль пишется
  в `users` (`touchAdmin`, статус всегда approved) — ошибка записи лишь `warn`.
- **Реклама в главах видео.** Авторы часто размечают рекламу отдельной главой («Реклама»).
  Мы передаём названия глав модели как основу для заголовков — то есть без фильтра сами
  приказываем ей сделать раздел «Реклама», и она слушается (реальный баг). Поэтому
  `stripAdChapters` выбрасывает такие главы **до** нарезки. Фильтр намеренно узкий: ловит
  только самостоятельные названия («Реклама»), но не «Реклама в играх» — иначе выкинем
  содержательный кусок. Регексп по кириллице — `\p{L}`, не `\w` (с флагом `u` тот ASCII-only).
- **Telegram не рендерит markdown-заголовки**. parse mode — **HTML**; заголовки блоков
  модель размечает `**жирным**`, форматтер сначала экранирует `< > &`, потом
  превращает `**…**` в `<b>…</b>`. Не добавляй сырой HTML до экранирования.
- **Язык ответа — всегда русский**, формат: `🔑 TL;DR` + смысловые блоки со списками.
- **Prompt-инъекции:** текст из веба/транскрипта недоверенный. `wrapUntrusted` оборачивает его
  в маркеры `⟦SOURCE <код>⟧…⟦/SOURCE <код>⟧` со случайным кодом на запрос, а `SAFETY_RULES`
  велят игнорировать инструкции изнутри блока. Оба системных промпта собираются как
  `composeSystemPrompt(task) = task + SAFETY_RULES`: **task-часть** — это то, что заменяет
  `SYSTEM_PROMPT_FILE` / `ARTICLE_PROMPT_FILE`, а **защита живёт в коде и подмешивается
  всегда**, поэтому кастомный промпт не может её потерять. Правила и обёртка ссылаются на
  общую константу `SOURCE_TAG` — не разъезжайся. Новый путь к LLM → обязательно через
  `wrapUntrusted` + `composeSystemPrompt`. Без действий/секретов в контексте инъекция максимум
  портит вывод: это снижение риска, не абсолют.
- **Поиск `/search` — InnerTube, неофициальный.** Эфиры отсекаются консервативно: нет
  длительности (`lengthText`) или есть любой признак эфира → видео не предлагаем. **Не
  ослабляй правило про длительность:** на живой выдаче (smoke, «lofi hip hop radio») из 15
  отсеянных эфиров явную пометку несли только 5, остальные 10 пойманы лишь отсутствием
  `lengthText`. Записи прошедших трансляций — обычные видео, проходят (так решил владелец).
  Сломался поиск — сначала `npm run search:smoke`, сырой ответ `--save` → в фикстуру теста.
- **Выбор в `/search` — командами, не кнопками** (так удобнее владельцу): под каждым видео
  `/sum_<код>` и `/art_<код>`, по нажатию Telegram отправляет команду в чат. id видео зашит
  в саму команду — результаты не храним. **id кодируется** (`encodeVideoId`: `_`→`_0`,
  `-`→`_1`): Telegram подсвечивает команду только из `[A-Za-z0-9_]`, на `-` подсветка
  обрывается. Ловится `bot.hears(PICK_COMMAND_RE)`, а не `bot.command` (имена динамические),
  до `bot.on('message:text')`. В реестр `COMMANDS` эти команды не входят. В шапке списка
  нет голых `/sum`: Telegram подсветит, а бот не поймёт.
- **Файлы — только форматы без новых зависимостей** (решение владельца: остальное перебор).
  Новый формат = запись в `BY_EXTENSION` + ветка в `readDocument` + тест; `/help` возьмёт
  список сам (`supportedExtensions`). Ссылка на скачивание содержит **токен бота** — в текст
  `DocumentError` её не кладём. Сообщение с файлом — не `message:text`, команды и `onLink`
  его не видят; GIF приходит и как `document` — `onDocument` пропускает `animation`.
  FB2 и субтитры разбираются регэкспами, сущности раскодируются **последними** (иначе
  `&lt;` после раскодирования примут за тег и вырежут).
  **Сущности в markdown — синтаксис**: `.md` мы не рендерим, поэтому `&nbsp;` раскодируем
  сами (вне кода, как CommonMark), иначе он литералом вылезает в шапке (`escapeHtml` →
  `&amp;nbsp;`) и в пересказе. Таблица имён в `document.ts` неполная (типографика), чужое
  имя остаётся как есть.
- **Тест модуля, который тянет `config` (напрямую или через `logger`)**, задаёт env в
  `before()` (включая обязательный `ADMIN_USER_ID`) и импортирует модуль динамически (см. `summarizer.test.ts`): статический импорт
  без `.env` роняет весь файл, а хук гоняет `npm run check` и там, где `.env` нет.
- Ошибки наружу — понятным текстом пользователю, не стек-трейсом (см. `onLink`).
- Провайдер настраивается (`LLM_BASE_URL`/`LLM_API_KEY`), всё ниже — **специфика
  дефолтного OpenRouter**; для OpenAI/Groq/Ollama просто поменяй baseURL+ключ+`MODEL`.
- Модели задаются в env — `MODEL` (обязателен) и `MODEL_FALLBACK` (опционален), **без
  встроенных дефолтов**; конкретную модель не навязываем. Список меняется, проверяй через
  `GET /api/v1/models`.
- Бесплатные слаги могут протухнуть → 404 (`unavailable`) или упереться в лимит → 429
  (`rate_limited`); оба обрабатываются в `summarizer` (для 429 — повтор по `Retry-After`).
  Если модель стабильно отдаёт 429 — поставь другой слаг.

## Статус и следующие шаги

Готовы Этапы 0–3 и бо́льшая часть Этапа 4: happy path, устойчивость (ретраи rdrr,
fallback-модель + повтор по 429, очередь `MAX_CONCURRENCY`, rate-limit),
шапка источника, метрики (строка `request`), Docker + compose + heartbeat-healthcheck.
Развёрнут на GitHub: `callmekoo/summarizer-bot`. Образ собирает CI
(`.github/workflows/docker.yml`) и пушит в GHCR (`ghcr.io/callmekoo/summarizer-bot`);
на сервере — `docker compose pull` (сборку с слабого VPS убрали, там `tsc` шёл минутами).

Готова команда **`/article`** (Этап 5): видео → статья в `.md`, с нарезкой по главам
(`chunker.ts`), вырезанием рекламы и настройкой промпта через `ARTICLE_PROMPT_FILE`.

Команды бота подсказываются сами (Этап 6): реестр в `commands.ts` → меню Telegram
(`setMyCommands`) + `/help`. Пересказ получил явное имя `/summary`, `/start` ужался до
приветствия. Текст со ссылкой без команды по-прежнему идёт в пересказ.

Готов **пересказ присланного файла** (Этап 8): `.md/.txt/.rst/.org/.adoc`, `.html`, `.srt/.vtt`,
`.fb2` → тот же пересказ, что по ссылке. PDF/DOCX/EPUB сознательно не делали (нужны зависимости).
Хендлер проверен smoke-прогоном с фейковым ctx и локальным LLM; в живом Telegram — за владельцем.

Готова команда **`/search`** (Этап 7): поиск на YouTube через InnerTube → 5 вариантов
со ссылками и командами `/sum_…` / `/art_…` → пересказ или статья. Проверено на живом
YouTube (`search:smoke`) и владельцем в Telegram. Из облачной песочницы youtube.com закрыт —
живой поиск гоняется локально.

Готов **доступ по заявкам и статистика** (Этап 9): заявка владельцу с кнопками, кулдаун
после отказа, бан, `/users`, `/stats` (запросы, токены, $ из `usage.cost` OpenRouter),
`/approve`/`/revoke`/`/ban`; SQLite (`node:sqlite`), именованный Docker-том `bot-data`.
Проверено юнит-тестами и smoke-прогоном с фейковым LLM; в живом Telegram — за владельцем.
Формат `usage.cost` OpenRouter из песочницы не сверить (openrouter.ai закрыт) — проверить
на первом живом запросе: если `/stats` показывает «$ —», поле пришло иначе.

Открыто (см. [PLAN.md](PLAN.md)):
- **webhook** вместо polling — и тогда healthcheck переделать на HTTP `/health`;
- опциональный **SQLite-кэш по URL** (база уже есть — `db/`);
- **лимиты** на пользователя или общий потолок трат — схема `requests`/`llm_calls` готова;
- **флуд от неодобренных**: ответ «на рассмотрении»/«отклонено» на каждое сообщение
  (осознанно не закрыто; вариант — не чаще раза в час);
- map-reduce для **пересказа** сверхдлинных текстов — сейчас там один проход с ориентиром
  по объёму (`summaryBudget`) и обрезка с предупреждением. Понадобится, если по логам
  окажется, что на часовом видео пересказ систематически игнорирует вторую половину:
  ориентир просит покрыть материал целиком, но не гарантирует этого.
